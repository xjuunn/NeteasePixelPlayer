# UI 与样式规范

目标：接入网易云页面时与现有界面风格一致，尽可能少改动原有样式。

## 1. 基本原则

- 复用现有 Compose + Material 3 组件与主题，遵循 `ui/theme/` 的颜色、字体、形状定义。
- 不硬编码颜色、圆角、间距、字号；统一从主题与现有常量获取。
- 不重写通用组件；优先在 `presentation/components/` 中查找可复用组件。
- 保持既有导航、底部播放条、播放队列、长按菜单等交互一致。

## 2. 页面位置

- 网易云页面放在 `presentation/netease/`：`dashboard/`（主页与 ViewModel）、`auth/`（登录）。
- 与其他来源（qqmusic、navidrome、jellyfin、gdrive、telegram）保持相同的目录与命名结构。
- 独立功能页（如歌单详情、歌手详情、搜索）纳入同一包内，不散落到 `presentation/screens/`。

## 3. 组件复用

- 歌曲/歌单列表项复用现有列表组件（如歌曲列表项、歌单卡片）与播放中高亮逻辑。
- 加载、空态、错误态复用现有组件（如 `presentation/screens/LibraryEmptyState.kt` 等）。
- 选择/添加歌曲复用 `SongPickerBottomSheet` 风格的底部弹窗。
- 需要新组件时，放在本来源包内并匹配现有视觉参数；通用性强的才提升到 `presentation/components/`。

## 4. 交互与反馈

- 加载、错误、空态必须有明确反馈，风格与本地库页面一致。
- 播放中状态、当前队列、迷你播放条沿用现有机制，不新增一套。
- 长列表使用现有分页/滚动模式；避免逐项多余动画造成卡顿。

## 5. 文案与本地化

- 文案使用现有字符串资源与命名规范，优先中文，保持简洁。
- 禁止使用 emoji（UI、注释、提交信息均禁止）。

## 6. 最小改动

- 仅在必要时修改原有文件；优先新增文件与扩展点。
- 若确需调整公共组件，保证向后兼容，并在提交说明中注明原因与影响范围。
- 改动完成后自测：列表、详情、搜索、播放、歌词、下载在浅色与深色主题下均正常。
